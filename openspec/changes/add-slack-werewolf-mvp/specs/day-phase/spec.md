# Spec Delta

## Purpose

主持白天階段：公布夜晚的死訊、給玩家時間討論、透過投票放逐一位玩家，並處理平票 PK 和獵人開槍。

## ADDED Requirements

### Requirement: 天亮公布死訊
天亮時，系統 SHALL 在頻道公布昨晚死亡的玩家。公告 SHALL NOT 透露死因和死者的角色，有多位死者時，名單順序 SHALL 隨機排列。沒有人死亡時，系統 SHALL 公告「昨晚是平安夜」。

#### Scenario: 昨晚有人死亡
- **WHEN** 昨晚 C 和 D 死亡（一位被刀、一位被毒）
- **THEN** 頻道公告「昨晚死亡的是 C、D」，不會說誰是怎麼死的，也不會公開他們的角色

#### Scenario: 平安夜
- **WHEN** 昨晚沒有人死亡
- **THEN** 頻道公告「昨晚是平安夜」

### Requirement: 死亡玩家的限制
已經死亡的玩家 SHALL NOT 能投票或使用任何能力，系統 SHALL 忽略死亡玩家的這些操作。系統 SHALL 在公布死訊時提醒死亡玩家不要在頻道發言（Slack 無法強制禁言，所以這部分靠玩家自律）。

#### Scenario: 死亡玩家嘗試投票
- **WHEN** 已經死亡的玩家按下投票按鈕
- **THEN** 這一票不被計入，系統只讓這位玩家看到「你已經死亡，無法投票」

### Requirement: 輪流發言
公布死訊之後（以及獵人開槍處理完之後），系統 SHALL 主持輪流發言，取代自由討論：
1. 每天從存活玩家中隨機選一位先發言，接著依照加入房間的順序（當作座位）往後輪，輪到最後一位就繞回第一位，跳過已經死亡的玩家，直到每位存活玩家都發言過一次
2. 開始時，系統 SHALL 在頻道公告這一輪的發言順序
3. 輪到某位玩家時，系統 SHALL 在頻道公告「輪到 X 發言（40 秒）」，並附上「結束發言」按鈕
4. 每人時限 40 秒。時間到、發言者按下「結束發言」，或房主用 `/werewolf next` 跳過時，就換下一位
5. 只有目前的發言者能按「結束發言」，其他人按了會被忽略並提示
6. 輪到 bot 時，系統 SHALL 公告「🤖BotN：過。」並立刻換下一位
7. 所有人都發言過之後，系統 SHALL 直接進入放逐投票。房主 SHALL 可以隨時用 `/werewolf vote` 結束輪流發言、直接進入投票

Slack 無法禁止非發言者打字，這部分靠玩家自律。

#### Scenario: 公告發言順序
- **WHEN** 第一天開始發言，存活玩家依加入順序是 A、B、C、D，隨機選到 C 先講
- **THEN** 頻道公告發言順序「C → D → A → B」，接著公告「輪到 C 發言（40 秒）」

#### Scenario: 跳過死亡玩家
- **WHEN** 加入順序是 A、B、C、D，B 已經死亡，從 A 開始
- **THEN** 發言順序是 A → C → D

#### Scenario: 時間到換下一位
- **WHEN** 輪到 C 發言，過了 40 秒
- **THEN** 系統公告「輪到 D 發言（40 秒）」

#### Scenario: 發言者提前結束
- **WHEN** 輪到 C 發言，C 按下「結束發言」
- **THEN** 系統立刻公告輪到下一位

#### Scenario: 不是發言者按結束發言
- **WHEN** 輪到 C 發言，D 按下「結束發言」
- **THEN** 系統不換人，只讓 D 看到「現在不是你的發言時間」

#### Scenario: 房主跳過發言者
- **WHEN** 輪到 C 發言，房主輸入 `/werewolf next`
- **THEN** 系統立刻公告輪到下一位

#### Scenario: 輪到 bot
- **WHEN** 輪到 🤖Bot1 發言
- **THEN** 頻道公告「🤖Bot1：過。」，並立刻輪到下一位

#### Scenario: 全部講完進入投票
- **WHEN** 最後一位發言者的時間到或按下結束發言
- **THEN** 系統直接進入放逐投票

#### Scenario: 房主提前結束發言
- **WHEN** 輪流發言進行中，房主輸入 `/werewolf vote`
- **THEN** 系統立刻進入放逐投票

### Requirement: 放逐投票
系統 SHALL 在頻道貼出投票訊息，用按鈕列出所有存活玩家，外加一個「棄票」按鈕。每位存活玩家可以投一票，時限 60 秒，時限內可以改票。所有存活玩家都投完時，系統 SHALL 立刻結束投票。投票結束後：
- 系統 SHALL 公開每個人投給誰
- 時限內沒有投票的玩家算棄票，棄票不計入任何人的票數
- 得票最多的玩家被放逐
- 所有人都棄票時，沒有人被放逐

投票期間，系統 SHALL 只讓投票者本人看到自己投給誰。

#### Scenario: 單一最高票
- **WHEN** 投票結束，C 得 3 票，D 得 2 票
- **THEN** 頻道公開每個人的投票，並宣布 C 被放逐

#### Scenario: 改票
- **WHEN** 玩家 A 先投 C，時限內又改投 D
- **THEN** A 的票最後算在 D

#### Scenario: 全部棄票
- **WHEN** 投票結束時沒有任何人得票
- **THEN** 頻道宣布今天沒有人被放逐，遊戲進入下一個夜晚

#### Scenario: 被放逐的玩家死亡
- **WHEN** C 被放逐
- **THEN** C 變成死亡狀態，系統不公開 C 的角色

### Requirement: 平票 PK
放逐投票出現多人同為最高票時，系統 SHALL 進入 PK：
1. 平票的玩家依照「輪流發言」的方式各自再發言一次（從加入順序最前面的平票玩家開始，每人 40 秒）
2. 接著重新投票，只能投給平票的玩家或棄票
3. 平票的玩家本人在 PK 投票中 SHALL NOT 投票
4. PK 投票仍然平票（或全部棄票）時，當天沒有人被放逐

#### Scenario: PK 發言
- **WHEN** C 和 D 平票
- **THEN** 系統公告 PK，接著依序公告「輪到 C 發言（40 秒）」、「輪到 D 發言（40 秒）」，兩人都講完後才進入 PK 投票

#### Scenario: PK 後分出勝負
- **WHEN** 第一輪 C 和 D 都是 3 票，PK 投票中 C 得 4 票、D 得 2 票
- **THEN** C 被放逐

#### Scenario: PK 後仍然平票
- **WHEN** PK 投票中 C 和 D 的票數還是一樣
- **THEN** 頻道宣布今天沒有人被放逐，遊戲進入下一個夜晚

#### Scenario: PK 中平票玩家不能投票
- **WHEN** C 在 PK 名單中，C 嘗試在 PK 投票中投票
- **THEN** 系統不計入這一票，只讓 C 看到「PK 中的玩家不能投票」

#### Scenario: PK 只能投給平票的玩家
- **WHEN** PK 投票訊息出現
- **THEN** 按鈕只有平票的玩家和「棄票」

### Requirement: 獵人開槍
獵人在夜晚被狼人擊殺，或在白天被放逐時，SHALL 可以開槍帶走一位存活玩家，也可以選擇不開槍，時限 60 秒，超時就當作不開槍。獵人按下「不開槍」時，系統 SHALL 私訊獵人確認。獵人被女巫毒死時 SHALL NOT 能開槍。開槍的時機：
- 夜晚被刀：天亮公布死訊之後、討論開始之前
- 白天被放逐：放逐公布之後、進入夜晚之前

獵人開槍後，系統 SHALL 在頻道公告「獵人 X 開槍帶走了 Y」，Y 隨即死亡。如果獵人死亡的當下勝負已經確定，就 SHALL NOT 開槍（見 win-condition）。

#### Scenario: 夜晚被刀的獵人開槍
- **WHEN** 獵人昨晚被狼人擊殺，天亮後選擇開槍帶走 D
- **THEN** 頻道公告「獵人 X 開槍帶走了 D」，D 死亡，接著進入討論時間

#### Scenario: 被放逐的獵人開槍
- **WHEN** 獵人在白天被放逐，選擇開槍帶走 D
- **THEN** D 死亡，系統判斷勝負，沒有結束就進入下一個夜晚

#### Scenario: 被毒死的獵人不能開槍
- **WHEN** 獵人昨晚被女巫毒死
- **THEN** 系統不會給獵人開槍的選項，也不會公告任何開槍相關的訊息

#### Scenario: 獵人選擇不開槍或超時
- **WHEN** 獵人選擇不開槍，或 60 秒內沒有回應
- **THEN** 沒有人因此死亡，系統不公開這位玩家是獵人，遊戲照常繼續

#### Scenario: 獵人選擇不開槍後收到確認
- **WHEN** 獵人按下「不開槍」
- **THEN** 獵人收到私訊「你選擇不開槍」，頻道不會出現任何訊息
